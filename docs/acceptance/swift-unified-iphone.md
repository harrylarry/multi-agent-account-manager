# 叠号 Swift 一次性真机验收

使用 T10 Issue 指向的 0.2.1 构建号 12，按现有方式签名，保持 Swift 的独立安装标识。覆盖安装到现有 Swift 测试版。只添加和操作非主力 Muse 账号。若只有一个非主力账号，可分别在两个槽登录并核对隔离。双账号与跨账号身份不匹配仍需两个不同的非主力账号。

## 1. 启动、隔离、代理和双域 Cookie

- 确认覆盖安装后 Swift 的测试资料仍在。进入「总览 → 隔离自检」，写入隔离 A 组资料，彻底关闭 App 再启动，点击「验证重启后隔离」，清理测试资料后运行 B/C。记录两个完成提示。
- 按 [T2 真机说明](swift-t2-iphone.md) 验证 HTTP、HTTPS、SOCKS5 三种实际出口。每种代理分别检查网页、原生额度和下一节的原生发送。用无效配置复查当前测试槽阻断，另一测试槽仍可用。记录正确出口、错误配置是否阻断，以及超时发生位置。
- 先用无代理测试槽打开 Muse 登录，确认内嵌视频可关闭且不重复全屏。非主力账号登录后「按域清点」，记录 muse.ai 和 meta.com 两域数量。填该账号邮箱，点「验证并保存到 Cookie 池」。导出加密 JSON，再用「选择 Cookie 文件」从「文件」App 选择同一文件，确认选中、可预览并能恢复。复查正确口令、错误口令及目标身份不匹配时的表现。
- 有可切换的 WebAuthn 实现和非主力 passkey 基线时，按 [T0 #17](https://github.com/harrylarry/multi-agent-account-manager/issues/17) 补做 S6。缺少任一前置条件时记待验。

## 2. 用 Rust Noise 验证总览、额度、订阅、审批和发送

- 确认「总览 → 隔离自检 → 试用 Swift Noise」关闭，彻底关闭后重开 App。
- 总览核对各槽的未读、待审批、进行中和空态。前台轮询切换 10、20、30 秒。用「新建对话」手动选非主力账号发送唯一短消息，确认收到回执、打开正确对话、只出现一条用户消息。按同样方式覆盖三种测试代理。
- 刷新额度，记录来源、最后更新时间、各槽显示及失败提示。区分真正的 0% 和未知值，确认短时间重进使用有效快照。对出现故障的槽记录 L1/L2/L3 实际可见结果。
- 前台保持总览，在另一台设备的官方网页用同一非主力账号产生一条新回复，确认红点和未读出现。打开对话看到最新消息后确认清除。短时断网后恢复，重复观察连接与回填，核对同一回复只计一次。
- 审批只测试非主力账号下的低风险待审批请求。若官方网页能产生，比较待审批计数、列表和详情，让请求自然过期，确认重启后旧请求不会变成可执行。观察真实载荷及长期授权绑定所需字段的缺口留给只读核验。没有出现审批时，记录「未触发」。
- 为发送不明场景只用一条唯一消息。点击后立即短时断网再恢复，若出现「需要核对」，等待约 26 秒观察是否在历史中匹配。另测彻底关闭并重开后续查。回执记结果和历史出现次数。

## 3. 加密备份和模型指纹

- 各导出一份轻量、全量和自定义备份。用可丢弃的测试槽分别进行合并、覆盖和恢复成新槽，按界面核对资料、代理与双域 Cookie。恢复同 UUID 后复查其他槽。分别验证错口令或损坏副本保持原状态，以及不用主口令、单用恢复码可恢复。调整保留份数，记录归档写入与恢复大致耗时。
- 打开非主力账号详情的「模型指纹」。进页或切账号时应无新增测量。手动确认一次，记录有效样本数、候选与置信度显示。重进核对历史留在原测试槽，未测的测试槽保持无记录。

## 4. 用 Swift Noise 重走关键路径

- 打开「试用 Swift Noise」，彻底关闭 App 再打开。用同一非主力账号新发另一条唯一短消息，核对回执、历史和账号归属。
- 复测前台订阅、未读清除和短时断网恢复。观察两种模式下是否有失败、重复消息、重复未读、回填缺失或代理错误。若 Swift 路径失败，关开关并重启，确认 Rust 路径恢复。

## 回执

提供机型、iOS 版本、App 版本和构建号，每项写「通过」「失败」或「未测」和一句可复核结果即可。Cookie 只报两域数量，代理用 A/B 代号描述出口，账号用测试槽代号。省略凭据、Cookie 值、恢复码和私人消息。自检的清理按钮只操作自检生成的测试资料。手动建立的非主力资料、备份和会话按需保留。
