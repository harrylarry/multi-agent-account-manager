# 叠号 Swift T2 真机验收

使用 [T2 Issue](https://github.com/harrylarry/multi-agent-account-manager/issues/20) 指向的 0.2.1 IPA。按现有方式签名，保持与 Tauri 日常版独立。Swift T1 与 T2 使用同一独立 Bundle ID，便于在 Swift 容器内升级。涉及真实 Muse 会话的步骤只用非主力账号。

## 隔离 A–C

1. 首页点「写入并检查 A / B」，彻底退出后重新打开，再点「验证重启后隔离」，最后清理测试资料。
2. 点「验证删除与恢复」。确认显示「B / C 组通过，测试资料已清理」。如果出现 WebKit 仍在释放资料的提示，彻底退出并重开 App，再点同一按钮继续。该组验证真实 WebKit 资料 ID 枚举、释放目标 WebView、删除只影响目标、双域合成 Cookie 加密往返、错误口令、保留原 UUID、新账号随机 UUID 及邮箱不匹配回滚。
3. 非主力账号同邮箱双槽重新登入，记录每槽均识别为正确账号。若两槽由同一快照恢复，两份 Cookie 值可相同。要测独立服务端会话，应分别在两个新槽重新登录并用脱敏哈希对照。

## 每账号代理

1. 在「账号资料、代理与 Cookie」新建两个槽。各自输入不同出口代理。分别用真实 HTTP、HTTPS、SOCKS5 端点进行同样的「保存并应用代理 → 检测代理 → 打开 Muse 登录」操作。保留端点协议、检测结果和脱敏出口判定。
2. 改错 A 的代理凭据，确认 A 检测失败、打开页面报代理错误，现有 B 会话持续正常。清除或修正配置后验证 A 恢复。若代理端确认返回 407，记录界面是否取消认证挑战。通过代理端日志或受控观测确认没有直连回退。
3. 测试 DNS prefetch、WebTransport、WebAuthn 的限制及是否仍有绕行。WebAuthn 登录 A/B 按已延期的 S6 条件执行。代理订阅缺测试地址。

## 双域 Cookie

1. 在非主力账号槽完成网页登录，回账号详情，填入该测试账号邮箱。点「按域清点」，记录 muse.ai 与 meta.com 的条数。对交接的 20 条基线逐域核对。遇缺域、设备绑定或分区 Cookie 时，记为待查并保留正确的提示。
2. 点「验证并保存到 Cookie 池」。用至少 12 字符的临时口令加密导出。文件与口令分别保留，回执只含域计数。
3. 选择同一 JSON 后确认界面显示文件名。输入备份口令，点「读取并预览 Cookie」，确认域计数。分别验证覆盖现有槽与恢复成新槽。确认旧槽 ID 保留，新槽 ID 不同，预期邮箱匹配。再分别用错口令和错邮箱测试，确认目标既有登录态保持。
4. 删除测试槽前分别验证「加密保留并删除」与「删除账号及本槽 Cookie」。清除目标后复查其他槽仍可用。

## 构建号 4 复测

- 打开无代理的测试资料，确认 Muse 登录页能打开，视频没有自动全屏。关闭后再从同一资料打开一次。
- 配置测试代理后重复检测和打开。记下超时出现于 Muse 入口检测、下载测速、叠号页顶部，还是 Muse 网页内部。
- 「验证并保存到 Cookie 池」若失败，记录具体提示。登录证明和邮箱未齐时，保留备份文件供后续验证。只记录 Cookie 域和数量。
