## 开发与交付顺序

| 批次 | 可见交付与依赖 | 验收条件 |
| --- | --- | --- |
| **A · 账号数据与登录恢复（下一批）** | iOS Cookie 导入预览，支持 JSON、Netscape 和请求头。请求头模式仅绑定选中服务的经确认来源。按账号显示登录状态、可观测的凭据有效期和手动重登入口。分组、搜索与排序一起回归。先实现解析、预览和写入保护，再接 UI。单账号时区的数据兼容可同步起步，改动涉及显示与服务请求时一起核对。 | 错误输入、跨域 Cookie、跨账号覆盖、写入中断和重启都有确定结果。覆盖前先预览，失败保留原会话。暂时断网或代理出错不能把账号判为登出或自动清除凭据。过期未知时如实显示。 |
| **B · 任务收件与代理管理** | 推进 Phase 1 的统一事件、两次稳定确认、去重、最近成功时间、前台原生检测与 DOM 回退。接回前台补查及完成/待审批通知设置，按 iOS 实测承诺可用范围。并行开发 Phase 2 的代理池、粘贴/订阅导入、按账号测速和配置校验。审批列表已有构建，写动作按真实协议和样本分批交付。 | 事件去重跨账号和重启验证，权限拒绝时保留前台红点。监测失败显示未知。代理更新失败保持旧数据，启用代理时故障必须阻断。审批提交前复核最新账号、会话、审批 ID 和到期时间，未知结果人工核对。 |
| **C · 会话、Hark 与加密备份** | 完成 Phase 3 原生会话列表与绑定，额度新增来源、窗口、更新时间和过期语义。按真实账号验 Hark REST/SSE/poll、断流恢复和 WebView 手工审批。备份实现轻量/全量/自定义、加密和恢复预览，独立于 Hark 真机推进。把单账号时区贯通原生、WebView 和额度展示。 | 断线保留绑定，旧额度显示过期，两路 Hark 事件只更新一次。备份错密码、坏密文、冲突和格式迁移均可核对，失败原子回滚。备份排除明文凭据和 WebKit 登录会话。临时分享的过期规则与密钥通道仍待产品裁决。 |
| **D · 房间与模型指纹产品化** | 可提前实现本地状态机、模板和崩溃恢复测试。依赖安全发送与恢复门禁后，按单 Muse 账号闭环 → 多账号接力与独立审核 → 自动分派、房间记录及复用推进。纳入上游话题、绑定、角色、共享上下文和附件表示。Muse 指纹入档与设置；Hark 先完成独立隔离发送 Spike，再做指纹。 | 至少覆盖三账号讨论和执行/审核分离的评审。切换目标、停止、迟到回复、丢 ACK 和重启均不能重复派活。交付物有可核验来源。三条有效探针才展示校准置信度。 |
| **Phase 5 · 独立评估** | Share Extension / Shortcuts、原生只读消息预览、Hark 进房间、多房间并行、跨设备备份按原计划进入可行性评审。 | 各自形成证据与范围决策后再排版本。 |

## 执行节奏与外部条件

- **首个候选**优先带账号导入与登录恢复这条完整操作路径，合并当前已打包审批及回前台补查的回归。用户下一次验包时集中验证账号导入、账号切换隔离、分组重启和审批入口。有 Hark 测试账号或待审批样本时同一次验包复用，缺样本则继续开发独立项。
- 每个合格切片做小提交并运行 CI。至少一项可完整操作的功能达到可验收状态时集中打包，提供 SHA、IPA、校验值和不超过一页的复测清单。已通过的旧场景只在改到相关路径时进入回归。无新证据的诊断不作为启用下一批开发的前置条件。
- 上游每次出现新 tag，在下一批开工时审计提交差异。选取项写入接续记录并注明哪些已存在、哪些待移植、哪些跨平台不适用或依赖裁决。移植代码保留来源与许可证要求。
- 保留 Phase 0 至 Phase 4 原有安全与真机门禁，各子项逐个标记 `CI_PASSED`、`DEVICE_VERIFIED`、`FAIL`、`BLOCKED` 或 `UNVERIFIED`。允许独立切片提前开发，正式发布以实际验收及用户授权为准。
