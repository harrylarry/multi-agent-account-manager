# 叠号 iPhone 重构方案

2026-11-27 · 待用户确认 · 当前交付为交互原型

先以新页面和用户路径定义功能，再适配现有接口与协议。沿用已验证的账号隔离、代理阻断、审批复查和发送台账。按新流程补齐缺失能力，并用独立证据标记原型、自动化和真机的验收状态。用户确认本方案后才开始 App 重构。

## 页面与交互

| 页面 | 入口与操作 | 返回及异常 |
| --- | --- | --- |
| 账号首页 | 顶栏为管理、服务下拉、总览、全局搜索。保留当前服务完整待办及账号列表，额度显示在账号行。账号主体打开该账号的独立网页，右侧信息按钮进入账号详情。 | 待办点击直达办理页面。继续支持已有账号排序、分组筛选和未读状态。列表更新保留当前筛选和位置。 |
| 会话 | 顶栏为管理、服务下拉和搜索。汇总当前服务所有可读取的账号会话，显示归属账号，点会话直达网页。 | 返回原列表位置。先展示已有缓存，增量刷新。区分首次加载、无会话、部分账号失败和旧数据。 |
| 总览 | 默认当前服务，依次为需要处理、未读回复、进行中的任务。待办和账号首页共用状态，未读与生成状态独立。 | 左上圆形返回。待办、回复或任务进入归属账号的相应页。 |
| 全局搜索 | 顶栏为搜索输入框和取消。跨 Muse／Hark 搜索账号与会话，结果注明归属，分别直达账号网页和指定会话。 | 从网页返回原搜索结果及查询词。取消后恢复服务、页面及列表位置。同步中和部分失败时保留可用结果，列明受影响账号并提供重试。 |
| 新增账号 | 服务菜单第三行进入单页表单。服务默认当前服务并可改选。依次填写备注、时区、语言、代理、可选 Cookie。底部为取消、创建并打开。备注留空由网页登录后获取邮箱。 | Cookie 留空进入网页登录，填写时先校验、导入再打开验证。提交失败原页保留设置。使用账号代理时首次打开前应用配置。 |
| 新建对话 | 底栏右侧圆形按钮。上方单选当前服务的账号，下方输入首条消息。发送前清楚显示账号归属，发送成功后直达该账号新会话。 | 区分发送中、确认发送、确定未发出、结果待核对。保留草稿。只有确认未发送才可重试，结果不明时先核对。 |
| 账号详情 | 只放账号设置和账号操作。页面标题用账号备注。子页用功能名作标题。 | 左上圆形返回，直接切换。会话统一从底栏会话或搜索进入。 |
| 管理 | App 级页面，隐藏服务控件和底栏。包含共享代理池、备份与迁移、检查更新。 | 管理从左进、向左退，返回进入前的页面。账号诊断放在账号详情。 |
| 空间／看板 | 底栏位置保留为设计预留。 | Muse 空间、Hark 看板协议与原型继续暂缓。当批 App 重构不依赖这两个页面。 |
| 产物 | 首版不放底栏。沿已打开的会话验证能读取的产物及回原会话路径。 | 产物入口位置随网页会话集成确定。会话列表保持单击直达。 |

顶部固定为交互区。圆形返回键与管理按钮同位置、同尺寸。总览与搜索从右进、向右退。其他页面直接显示。总览、搜索及各子页隐藏底栏和新建对话按钮。原生 Liquid Glass 用于顶部控件、底部导航和新建对话按钮，内容区确保文字与状态对比度。面向支持该材质的系统，兼顾深浅色、降低透明度和减少动态效果。

### 排版与文案

| 层级 | 原型基准 | 用途 |
| --- | --- | --- |
| 页面标题 | 28，字重 700 | 独立页面只显示一个主标题。账号首页、会话列表和搜索保留语义标题，视觉上直接进入列表或搜索结果。 |
| 分区标题 | 17，字重 600 | 需要处理、未读回复、进行中的任务、账号设置等并列区块。 |
| 正文与控件 | 16，字重 400／600 | 正文、输入值为常规字重。列表名称、表单标签、主要按钮和状态摘要使用强调字重。 |
| 辅助文字 | 13，常规字重 | 说明、来源、时间和列表辅助信息。 |
| 底栏标签 | 12，选中时强调 | 短标签配合图标和选中底色。 |

标题、正文和控件使用系统字体，按字级统一行距与字重，实施时适配系统文字大小。顶栏、总览、账号详情及子页省去重复服务名和账号副标题。跨服务搜索结果、网页落点和包含多个账号的备份预览保留必要归属。

## 接口复用和补齐清单

接口名对应当前仓库。复用表示已有入口或逻辑可适配，完整新流程需按最后一列验证。

| 功能 | 可复用的接口或实现 | 需要补齐或核实 |
| --- | --- | --- |
| 顶栏、底栏、账号网页 | `get_manager_state`、`manager-state-changed`、`select_provider`、`switch_account` 与现有独立 WebView | 原生玻璃控件与现有页面的组合、安全区、键盘、返回栈、快速切号时的账号归属和列表位置。版本门槛在实施时核实。 |
| 账号设置、分组 | `rename_account` 已支持备注、分组、时区。继续沿用 `reorder_accounts` 与 `remove_account`。 | 现有分组来自账号字段，独立持久化分组目录需补齐。方案按服务隔离分组。同服务内按已保存的账号归属检测占用，无分组不可删除。首次提示与确认删除时都检查，检查和删除使用同一事务。删除空组不修改任何账号。语言需明确网页和服务请求的实际生效范围。 |
| 新增账号 | `add_account`、`preview_account_cookies` 和现有 WebView、Cookie 写入核验 | 当前新增接口只收服务、备注、Cookie。补齐时区、语言、代理与首次打开的配置顺序。失败时保留草稿，避免残留半创建账号或错服务 Cookie。 |
| 会话列表与网页跳转 | Muse 的 `list_muse_sessions`、`open_muse_thread`，以及已有最近会话标识 | 按服务和账号缓存、差量合并、不支持增量时按快照对比。核实分页、删除、归档和旧结果处理。Hark 全量读取与指定会话网页跳转待验证。 |
| 总览与搜索 | 账号快照、Muse 列表和未读读取、现有任务与审批事件 | 共用待办状态及来源时间。手动审批查询应同步首页计数。账号索引遍历两服务，按能可靠读取的会话建立索引。补齐读取失败和重试、账号移除或登录失效时的索引失效、跨服务返回栈。 |
| 新建对话 | Muse 的隔离会话与发送探针、Hark 的隔离发送验证、持久化发送台账 | 诊断命令用于验证。需开发面向用户的两服务创建、首条消息发送、ACK 与会话 ID 关联和网页直达。确认请求发出后遇到断流或崩溃时的核对路径。 |
| 共享代理池与账号代理 | `manage_proxy_pool`、`apply_proxy_pool_entry`、`muse_native_get_account_proxy`、`muse_native_clear_account_proxy`、`measure_account_proxy` | 管理页统一录入和订阅，批量导入增加分号分隔并验证解析、去重和脱敏。账号页只选池条目，选中即可检测。现有测速针对已配置账号，需补齐对未保存选择的只读测速，禁止为测速临时改写正式账号设置。保存才应用，明确保存、连通和阻断状态。 |
| 登录恢复 | `inspect_account_cookies`、`preview_account_cookies`、`transfer_account_cookies` | 同一按钮从预览切换到确认导入。更改输入使预览失效，导入成功后打开网页。复制本机 Cookie 使用 iOS 仅本机剪贴板，目前原生固定 60 秒。补齐 30 秒、60 秒、5 分钟选择并保持 Cookie 自身有效期。 |
| 任务与通知 | `observe_account_tasks`、`set_account_task_notifications`、Muse 回前台未读补查与 Hark 现有只读恢复 | 区分「当前没有任务」「状态待确认」「检查失败」「有未读回复」。核对手动查询与自动判断的复测规则。检查未读回写时机、通知权限、低电量和后台恢复。 |
| 审批 | `muse_native_approvals_probe`、`decide_muse_approval` 与既有范围、有效期、提交台账 | 查询和处理结果回写共用待办状态。失效或结果不明时刷新核对。Hark 保留进入对应网页处理。 |
| 额度 | `muse_native_quota_probe`、`trigger_quota_sync` 和现有账号额度快照 | 统一展示每账号来源、更新时间、旧值和刷新结果。批量请求需区分完成、跳过和失败。额度留在账号页及详情，管理中的版本检查不夹带额度入口。 |
| 模型指纹 | `muse_native_fingerprint_probe`、`hark_fingerprint_probe` 和已有历史记录 | 页面只呈现手动检测和结果。实施前明确旧版曾保存的自动重测设置如何停用，避免移除开关后继续自动消耗额度。Hark 检测仍需满足隔离发送和完整回复门禁。 |
| Hark 回复补同步 | `hark_recover_replies`、已有卡片展开 | 真机核对断流补回、重复更新及卡片类型。网页直达仅在真实会话归属与定位已验证时开启。 |
| 备份、恢复和 Wi-Fi | `export_account_backup`、`preview_account_backup`、`restore_account_backup`、`manage_lan_backup` | 凭据随文件备份为新能力，默认关闭。仅在明确勾选后，经授权从各账号的独立存储读取并加密。恢复前列出账号、类型、冲突及处理范围并二次确认。验证错误口令、过期 Cookie、重复账号、部分失败和回滚。当前设计中的凭据选项只用于文件备份，Wi-Fi 凭据迁移另行确认。 |
| 诊断与更新 | 账号代理测速、Muse／Hark 诊断、`check_for_updates` 和现有 iOS 更新页 | 诊断只在账号详情，输出按账号脱敏。检查更新在全局管理。保留原有技术诊断和错误细节，按服务与测试能力展开。 |
| 产物 | Muse 已有指定会话跳转，Hark 可解析部分主会话卡片 | Muse 产物字段和归属、Hark 稳定卡片与文件识别、按真实账号返回原会话均需验证。保持只读和代理隔离。 |

## 审核与实施顺序

1. 当前已通过设计审核的页面为新增账号、新建对话、会话、总览与全局搜索。账号操作、管理和分组删除以本轮原型待确认。
2. 确认后先实现导航、账号打开、账号操作与玻璃样式。复测简单返回、跨服务搜索往返、账号分组删除校验和待办跳转。
3. 接入会话缓存、全局搜索和总览数据，再补新建对话的产品级发送与凭据备份。未打通的服务读取或跳转按各自能力如实显示。
4. 在 iPhone 上用两个独立账号与正确／错误代理做对照。必测 Cookie、审批确认、会话归属、发送结果不明后的禁止重复发送、代理故障阻断，以及备份恢复预览。真机证据未完成前标记 `UNVERIFIED`。

原型使用示例数据。协议和安全行为以实际实现与验收为准。
